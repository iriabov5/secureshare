# React-интерфейс

Одна кодовая база адаптируется CSS media queries: до 760 px боковая панель превращается в верхнюю навигацию, строки списка становятся компактными, фильтры остаются доступными.

## Структура и ответственность

- api/client.ts — fetch, cookies, CSRF cache, безопасные ошибки; изменяющие запросы автоматически не повторяются.
- auth/AuthContext.tsx — состояние сессии. 401 очищает клиентскую сессию; SESSION_EXPIRED показывает причину завершения на login, CSRF cache сбрасывается; сбой сети даёт retry без ложного выхода.
- auth/AuthPage.tsx — вход и регистрация с общими полями. Пароль не переносится в history после регистрации.
- files/useFiles.ts — загрузка metadata, отмена устаревшего запроса и обновление списка.
- files/FilesPage.tsx — рабочее пространство, поиск, сортировка и файловые действия.
- files/useFileIntegrity.ts — ручная проверка, отмена при смене формата и хранение результата в состоянии страницы.
- files/UploadDialog.tsx — выбор файла, dropzone, валидация, состояние отправки и подтверждение API.
- security/ — список активных сеансов, подтверждение отзыва и обработка ошибок.
- ui/WorkspaceLayout.tsx — общие навигация, аккаунт и заголовок разделов.
- ui/ — общие кнопка, поле, бренд и сообщения. Иконки Lucide поставляются в bundle; внешних шрифтов/CDN нет.

Компоненты не принимают решения о серверных полномочиях. Доступ проверяют Spring Security и Method Security. Регистрация JSON, login — form-urlencoded через UsernamePasswordAuthenticationFilter, logout — LogoutFilter. CSRF включён, после смены Authentication токен запрашивается заново. Cookie HttpOnly, SameSite=Lax; Secure выключен только в local-профиле.

## Дизайн и состояния

Тёмная навигация, светлый фон, белые поверхности и синий акцент. Сводка показывает фактическое количество и сумму размеров доступных файлов; ограничение 10 MiB задаёт сервер. У списка есть загрузка, пустое состояние, поиск без совпадений и ошибка с ручным обновлением. Файл появляется в списке после ответа 201.

Нативный dialog удерживает фокус, закрывается Escape до отправки и возвращает фокус инициатору. Есть явные labels, autocomplete, live outputs, focus-visible, skip link и reduced-motion. Названия файлов React экранирует как текст. На телефоне поле пароля имеет 16 px, чтобы не вызывать автоматическое увеличение.

## Запуск и проверка

Из корня: npm ci; npm run dev. Vite 5173 проксирует /api на backend 8080. Для сборки ./gradlew bootJar; Node.js 26 LTS нужен только для build. Lockfiles фиксируют npm и Gradle зависимости. npm run check:frontend проверяет TypeScript, ESLint, форматирование и Vitest. Корневой ./gradlew check добавляет тесты и покрытие backend.

python3 scripts/browser-check.py запускает собранный jar, отдельные PostgreSQL и SeaweedFS, затем Chromium из официального Playwright 1.64.1 в тестовом image с Node 26/npm 12 (frontend/e2e/Dockerfile). Скрипт использует случайные тестовые credentials и порты, удаляет собственные контейнеры в finally. На Docker Desktop браузер обращается к временному серверу через host.docker.internal. Сервер слушает 0.0.0.0 только на время этой проверки; обычная конфигурация остаётся loopback. В Linux нужен Docker с поддержкой host-gateway (скрипт добавляет соответствующий host).

Playwright проверяет 1440×1000 и 390×844: регистрацию, вход, три настоящих upload, поиск/сортировку, проверку целостности, байты download, изоляцию двух пользователей, восстановление списка после reload, logout, фокус dialog, overflow и CSP. В тестах создаются демонстрационные документы; UI получает их обычным API. Снимки: docs/screenshots.

Ограничения: список без pagination, скачивание ограниченного файла целиком в памяти браузера, нет sharing/delete/MFA/восстановления пароля.
